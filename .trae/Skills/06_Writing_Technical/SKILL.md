# 技术写作

核心判断只有一条：**读者读完能不能复述你的结论和依据**。文采是次要的。

## 一、先定文档类型

不同类型结构完全不同，别混着写：

| 类型 | 读者 | 核心要求 |
|:---|:---|:---|
| 毕业论文 | 答辩老师 | 结构完整、有方法、有验证、格式合规 |
| 课程报告 | 任课教师 | 覆盖指定要点、体现个人理解 |
| 技术方案 | 团队 / 客户 | 可执行、有取舍理由、有风险 |
| 项目 README | 陌生人 | 三十秒内知道这是什么、怎么跑 |
| 需求文档 | 开发与测试 | 边界清晰、可验证 |

## 二、结构与论证

**学术类（论文 / 报告）通用骨架**

1. 摘要：背景一句、做了什么、怎么做的、结果如何、意义一句
2. 引言：问题从哪来，现有方案缺什么，本文补什么
3. 相关工作 / 技术基础：只写和本文相关的，不做文献堆砌
4. 方法 / 设计：**为什么这样设计**比"是什么"重要
5. 实现 / 实验：环境、数据、参数、对照组
6. 结果与分析：先给结论再给数据，解释异常
7. 局限与展望：主动说不足，比被问出来强
8. 参考文献

**每一章的写法**：先给本章结论，再展开推导，最后小结衔接下一章。不要"总分总"写到读者找不到重点。

## 三、论证的三条硬规则

1. **每个论断都有依据**：数据、引用、实验，或明确标注为主观判断
2. **区分事实与推测**：写"实验显示 X"和"可能因为 Y"要分开表达
3. **不夸大**：不用"显著提升""革命性""完美解决"，给出具体数字

## 四、格式规范（中文学术常见）

- 图表：图题在图下、表题在表上，全文连续编号（图 3-1、表 3-2）
- 正文必须提到每一张图表（"如图 3-1 所示"），否则删掉
- 公式：独立成行、右侧编号、符号首次出现时说明
- 引用：正文用 `[1]` 或作者年份，与文末列表一一对应
- 参考文献：期刊 / 会议 / 学位论文 / 网页格式不同，别混用
- 代码：等宽字体、保留缩进、过长截断并说明

## 五、去 AI 腔

这些是最明显的机器味，逐条清掉：

| AI 常见写法 | 改成 |
|---|---|
| "在当今数字化时代，随着…的快速发展" | 直接说问题 |
| "不仅…而且…" 连用三次 | 拆成两句 |
| "值得注意的是""综上所述""总而言之" | 删除，或换成具体过渡 |
| "赋能""抓手""闭环""生态" | 用具体动作替代 |
| 每段都是"首先…其次…最后…" | 打散，按逻辑而非序号组织 |
| 形容词堆砌："高效、稳定、可靠、灵活" | 给一个可验证的事实 |
| 空泛结论："大大提升了用户体验" | "首屏加载从 3.2s 降到 1.1s" |

上表只处理了最浅的一层。AI 味分四层，**越深越致命**：

| 层级 | 表现 | 处理难度 |
|---|---|---|
| 词汇层 | 套话、AI 高频词、万能形容词 | 容易，替换即可 |
| 句式层 | 否定排比、工整对偶、句子长度匀速 | 中，需要打散节奏 |
| 结构层 | 每节结尾落一句金句、导游式路标、结尾回扣升华 | 难，需要重排 |
| 经验层 | 细节可替换、判断两头堵、作者不在场 | 最难，且无法靠删改解决 |

**关键结论：只做减法有天花板。** 有对照实验显示，把词汇线索全部洗掉之后，熟练读者依然能 100% 识别出 AI 文，靠的是结构和原创性；只做结构手术、不注入真实素材的版本，评分只比原稿高 0.4 分，评委的原话是"干净得像消过毒"。

**经验层是唯一伪造不了的一层。** 同一场盲测里，注入真实素材的版本 8.6 分，原稿 5.5 分。

具体做法：

1. **先挖素材，再动刀。** 问作者两三个只有他知道的问题：「第一次碰到这个问题是什么时候，当时在干什么？」「这个结论你自己踩过什么坑？」挖不到就放 `[待补：建议方向]` 占位符，**绝不编造**经历、场景、对话、数字。编造的人味被识破一次，作者信用清零。
2. **判断要能押注。** 两头堵的表述（"既有利也有弊"）是安全的废话。改成可以被未来验证的具体判断，但方向必须来自作者真实立场。
3. **不确定要长在句子里**（"不过这个我还没验证过"），不要单独成段做免责声明。
4. **别把真人特征当毛病修掉。** 奇怪的具体细节、矛盾的情绪、口语重复、不完美的句子，是真人证据，保护它们。

改写方法：把每段读出来，问"这句话换个题目还成立吗？"如果成立，说明它没信息量。素材自检句是："这个细节换成别的还成立吗？"——成立的只是查资料式的具体，不成立的才是真经历。

## 六、报告原型

写报告前先回答一个问题：**读者拿它干什么？** 选错原型是最贵的错误。

| 读者要 | 原型 | 特征 |
|---|---|---|
| 引用你的数字 | 学术型 | 竖版、方法论透明、图表编号、预先反驳自己 |
| 开会说服人 | 咨询 deck 型 | 16:9、一页一结论、标题就是结论句 |
| 理解一个群体 | 调查型 | 双栏、问卷原题随图、大数字视觉锚 |
| 查具体数据 | 研报型 | Exhibit 编号、表格密度高、中性描述 |
| 同行评审 | 论文型 | IMRaD、contributions 显式列出 |
| 理解一个领域并据此行动 | 科普型 | 场景开篇、口径进侧栏、结尾交付工具箱 |

把要被引用的东西做成 deck，没人能引；把要开会用的做成 60 页学术报告，没人会读。

**五条硬规矩：**

1. **每个数字都要有分母。** "多数企业正在部署 agent"是废话；"951 家企业里 7% 跑通（Bain, 2026）"才是数据。百分比后面没有 N，读者无法判断它是不是噪声。
2. **图表标题写结论，不写主题。** ❌「按职能划分的招聘计划」✅「研发与销售扩张，客服收缩」。研报型例外，查数的读者要中性描述。
3. **预先反驳自己。** 结论之后专门写一段：这个发现可能被什么替代解释推翻，排除了哪些，还剩哪些没排除。主动降级结论反而更容易被引用。
4. **附录是参考文献表，不是数据表转印。** 一条来源一行，附录长度跟来源数走，不跟数据点数走。体量控制在正文的 10% 以内。
5. **不写"我是怎么做的"。** "脚本一开始抓错了文件"是工作日志。判据：删掉这句，读者对结论的判断会不会变？不变就删。样本框、纳入排除标准、口径规则属于方法论，必须写。

**顺序不能倒：** 定原型和一句话 → 建数据表 → 写正文 → 补机制与文献定位 → 做图 → 逐页自检。先写正文再补数据，一定会留下"这句很顺但我没核过口径"的句子。

## 七、摘要写法

五句话，不要多：

1. 这个领域存在什么问题（一句）
2. 本文提出了什么（一句）
3. 用了什么方法（一句）
4. 达到了什么结果，带数字（一句）
5. 有什么意义或适用边界（一句）

不要出现"本文首先…然后…最后…"这种目录式摘要。

## 八、修改流程

1. **砍**：删掉不服务于结论的段落，通常能砍 20%
2. **调序**：结论前置，论据跟随
3. **改句**：长句拆短，被动改主动，去掉修饰词
4. **查格式**：编号、引用、图表题、页边距
5. **读一遍出声**：读着别扭的地方就是需要改的地方

## 九、交付要求

- 中文正文用中文标点，中英文之间加空格
- 术语首次出现给英文原文，之后统一用中文
- 数字与单位之间空格（"128 元"），百分号不加空格（"12%"）
- 不写"我认为""笔者觉得"，除非明确是观点章节
