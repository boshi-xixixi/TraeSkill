# 演示与答辩

演示不是把文档搬上幻灯片，是**在有限时间里让听众记住一件事**。

## 一、先定三件事

动手做之前必须确定：

1. **时长**：5 分钟和 20 分钟是两种完全不同的结构
2. **听众**：评委（看方法严谨性）、投资人（看市场与团队）、同学（看有趣程度）
3. **唯一目标**：散场后你希望他们记住哪一句话

写下来，贴在屏幕边上。后面每一页都要为它服务。

## 二、结构模板

**答辩 / 项目汇报（8–10 分钟）**

| 段落 | 时长 | 内容 |
|:---|:---|:---|
| 开场 | 30s | 一句话说清做了什么，不要自我介绍 |
| 问题 | 1min | 谁在什么场景下遇到什么麻烦，给一个具体例子 |
| 方案 | 2min | 你的解法，配一张真实界面或架构图 |
| 关键决策 | 1.5min | 为什么这么选，放弃了什么 |
| 结果 | 2min | 数据、截图、用户反馈 |
| 局限与计划 | 1min | 主动说不足 |
| 收尾 | 30s | 回到开场那句话 |

**路演（3–5 分钟）**：问题 → 方案 → 数据 → 团队，四段，每段不超过 90 秒。

## 三、每页的规则

- 一页一个观点，标题就是观点（"Q3 转化率下滑 12%"而不是"数据分析"）
- 文字不超过 6 行，每行不超过 12 字
- 能用图就不用表，能用表就不用字
- 字号：正文 ≥ 20pt，标题 ≥ 28pt，现场后排要看得见
- 关键数字放大，一页只放大一个
- 不要动画和转场，评审只会觉得浪费时间

## 四、讲稿写法

讲稿不是逐字稿，是**提示卡**：

```
[页 3 · 问题]
- 现在学生查课表要开三个 App（举例：教务网 + 群通知 + 备忘录）
- 痛点：信息散，错过就补不回来
- 过渡句：所以我们想，能不能让一个入口把这件事做完
```

每页 3 条以内，每条不超过 15 字。逐字稿念出来一定像背书。

## 五、时间控制

- 排练至少 3 次，掐表
- 准备**两个版本**：完整版和你超时时能砍掉的 20%
- 标记"可跳过页"，现场被提醒时间直接从这些页跳
- 语速参考：每分钟 200–240 字（中文）
- 留 10% 缓冲给紧张导致的卡顿

## 六、问答准备

按这个顺序准备 15 个问题：

1. **为什么不用现成方案？**（必问）
2. **你的方案有什么局限？**（必问，答好加分）
3. **数据怎么来的，样本多大？**
4. **如果真的上线，最大的风险是什么？**
5. **成本多少，谁来付钱？**
6. **如果重做一次，你会改什么？**

回答结构：**先给结论 → 再给依据 → 最后给边界**。不要"这个问题问得好，我觉得…"。

不知道就说"这块我还没验证，我目前的理解是…"，比硬编强。

## 七、PPT 视觉

- 一套配色（主色 + 一个强调色 + 灰阶），不要五颜六色
- 字体统一两种：无衬线做正文，一种做标题
- 对齐比装饰重要：左对齐、等间距、同一套网格
- 深色底适合投影环境亮的场地，浅色底适合打印
- 截图用真实界面，不要用占位图

## 八、交付前检查

- [ ] 每页标题单独看能不能串成完整故事
- [ ] 没有超过 6 行的页面
- [ ] 所有数字都有出处
- [ ] 演示文件在目标电脑上能打开（字体嵌入、视频外链）
- [ ] 备份一份 PDF，防止现场版本不兼容
- [ ] 计时排练过，且知道砍哪几页
